2. SystemdTransientWorkerHost.stream() does not have equivalent K5 deadlines.

File:
  /home/sydeco/Dev/SYDECO_LIGHTML_V2_DEV/sydeco_lightml_core/worker.py

Relevant lines:
  1034-1041: SystemdTransientWorkerHost.stream() forwards /stream to worker.
  1056-1058: HTTPConnection is created with timeout=self._timeout.
  1064-1081: stream loop reads lines until EOF and yields {"data": ...}.
  1082-1095: socket.timeout maps to generic InferenceTimeout and recycles.

Baseline conclusion:
  The systemd production-path stream uses the ordinary inference timeout as
  socket inactivity timeout. It does not independently enforce:
    - stream_first_chunk_timeout;
    - stream_idle_timeout;
    - stream_total_timeout by monotonic absolute deadline.


3. Systemd EOF currently means success/completion.

File:
  /home/sydeco/Dev/SYDECO_LIGHTML_V2_DEV/sydeco_lightml_core/worker.py

Relevant lines:
  1064-1067:
    line = resp.readline()
    if not line:
        break

Baseline conclusion:
  EOF exits the generator normally. Because the private worker-to-Core stream
  has no explicit completed/error terminal frame, Core cannot distinguish normal
  completion from worker disappearance, restart, or abnormal connection close.


4. Adapter stream errors are encoded as normal data by worker_runtime.py.

File:
  /home/sydeco/Dev/SYDECO_LIGHTML_V2_DEV/sydeco_lightml_core/worker_runtime.py

Relevant lines:
  269-280: /stream sends 200 application/x-ndjson and writes each adapter chunk
           through _send_ndjson_data().
  283-288: exceptions during /stream are logged and then sent through
           _send_ndjson_data({"error": "internal error"}).

Baseline conclusion:
  The internal frame becomes:
    {"data": {"error": "internal error"}}
  SystemdTransientWorkerHost.stream() treats this as ordinary chunk data, not
  as a worker error. This confirms the reviewer's concrete error-framing defect.


5. Public streaming batch requests silently use only items[0].

File:
  /home/sydeco/Dev/SYDECO_LIGHTML_V2_DEV/sydeco_lightml_core/server.py

Baseline conclusion:
  Streaming batch requests do not get a controlled 4xx. The first item is

6. Public stream framing already has public-level terminal event handling.

File:
  /home/sydeco/Dev/SYDECO_LIGHTML_V2_DEV/sydeco_lightml_core/server.py
